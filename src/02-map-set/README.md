## 1. Зачем Map, если есть объект

| Вопрос             | Обычный объект `{}`                                                        | `Map`                                      |
| ------------------ | -------------------------------------------------------------------------- | ------------------------------------------ |
| Типы ключей        | только `string` / `symbol` (числа → строки, объекты → `"[object Object]"`) | **любые**: числа, объекты, функции, `NaN`  |
| Ключи из прототипа | есть (`toString`, `constructor`…)                                          | нет, Map пустой по-настоящему              |
| Порядок            | сложный (числовые ключи идут первыми)                                      | всегда **порядок вставки**                 |
| Размер             | `Object.keys(o).length` — O(n)                                             | `map.size` — O(1)                          |
| Итерация           | `Object.entries(o)`                                                        | `for (const [k, v] of map)` напрямую       |
| Частые add/delete  | медленнее                                                                  | оптимизирован под это                      |
| JSON               | ✅ `JSON.stringify` работает                                               | ❌ даёт `"{}"`, нужен `Object.fromEntries` |

**Правило выбора:**

- фиксированная форма данных (DTO, конфиг, props), нужен JSON → **объект**;
- динамические ключи (id, слова, ввод пользователя), частые добавления/удаления, нужен `size` или порядок → **Map**;
- ключи — объекты → **Map** (или **WeakMap**, см. ниже).

## 2. Карточки: Map

### `new Map(entries?)`

- **Принимает:** массив пар `[[key, value], ...]` или любой iterable пар (например, другой Map).
- **Возвращает:** новый Map.

```ts
new Map([
  ['a', 1],
  ['b', 2],
]);
new Map(Object.entries(obj)); // из объекта
new Map(users.map((u) => [u.id, u])); // индекс по id
new Map(otherMap); // shallow copy Map
```

### `map.set(key, value)` → сам Map

- Добавляет или **перезаписывает**. Возвращает **сам Map**, поэтому можно чейнить: `m.set('a', 1).set('b', 2)`.
- Перезапись **не меняет позицию** ключа в порядке обхода.

### `map.get(key)` → значение | `undefined`

- ⚠️ Не отличает «ключа нет» от «значение равно `undefined`». Если такое возможно — проверяй через `has`.

### `map.has(key)` → boolean, `map.delete(key)` → boolean, `map.clear()`

- `delete` возвращает `true`, если ключ был, иначе `false`.

### `map.size` — **свойство**, не метод

### Обход: `for...of`, `keys()`, `values()`, `entries()`, `forEach`

```ts
for (const [key, value] of map) { ... } // пары
[...map.keys()]; // keys() — ИТЕРАТОР, не массив
Array.from(map.values());
map.forEach((value, key) => { ... }); // ⚠️ сначала value, потом key!
```

### `Map.groupBy(items, fn)` (ES2024) → Map групп

```ts
Map.groupBy(users, (u) => u.role); // Map { 'admin' => [...], 'dev' => [...] }
```

### Как сравниваются ключи

Алгоритм **SameValueZero**: как `===`, но `NaN` равен `NaN`.

- `1` и `'1'` — **разные** ключи;
- объекты — **по ссылке**: `map.get({ id: 1 })` не найдёт ключ, добавленный другим объектом `{ id: 1 }`.

## 3. Карточки: Set

| Метод            | Что делает                      | Возвращает             |
| ---------------- | ------------------------------- | ---------------------- |
| `new Set(iter?)` | создать, дубликаты выкидываются | Set                    |
| `add(v)`         | добавить (повтор игнорируется)  | **сам Set** (чейнится) |
| `has(v)`         | есть ли значение                | boolean — **O(1)**     |
| `delete(v)`      | удалить                         | boolean: было ли       |
| `size`           | количество                      | число (свойство)       |
| `[...set]`       | в массив                        | массив                 |

```ts
[...new Set(arr)]; // убрать дубликаты, O(n)
new Set('hello').size; // 4 уникальных символа
new Set([{ id: 1 }, { id: 1 }]).size; // 2 — объекты по ссылке!
```

### Почему `set.has` быстрее `array.includes`

- `includes` идёт по массиву от начала → **O(n)** на каждую проверку.
- `has` — хеш-таблица → **O(1)** в среднем.
- Внутри цикла это разница между O(n × m) и O(n + m):

```ts
// ❌ O(n × m)
a.filter((x) => b.includes(x));
// ✅ O(n + m)
const setB = new Set(b);
a.filter((x) => setB.has(x));
```

### Алгебра множеств (ES2025, Node 22+) — все возвращают **новый** Set

| Метод                      | Смысл                  | `A={1,2,3}`, `B={2,3,4}` |
| -------------------------- | ---------------------- | ------------------------ |
| `A.union(B)`               | A ∪ B                  | `{1,2,3,4}`              |
| `A.intersection(B)`        | A ∩ B                  | `{2,3}`                  |
| `A.difference(B)`          | A \ B                  | `{1}`                    |
| `A.symmetricDifference(B)` | только в одном из двух | `{1,4}`                  |
| `A.isSubsetOf(B)`          | A ⊆ B                  | `false`                  |
| `A.isSupersetOf(B)`        | A ⊇ B                  | `false`                  |
| `A.isDisjointFrom(B)`      | нет общих              | `false`                  |

⚠️ `intersection` **не гарантирует порядок** элементов из `A`: по спеке он обходит **меньшее** из двух множеств. `new Set([1,2,3,4]).intersection(new Set([4,2]))` → `{4, 2}`. Если порядок важен — `[...a].filter((x) => setB.has(x))`.

## 4. WeakMap и WeakSet

|               | Map / Set                | WeakMap / WeakSet                                    |
| ------------- | ------------------------ | ---------------------------------------------------- |
| Ключи         | любые                    | **только объекты** (иначе `TypeError`)               |
| Держит ключ   | сильно (объект не умрёт) | **слабо**: объект может собрать GC — запись исчезнет |
| Обход, `size` | есть                     | **нет** (содержимое может исчезнуть в любой момент)  |

**Когда:** хранить данные «рядом» с объектом и не мешать ему умереть: кэш для DOM-узлов, приватные данные экземпляров, пометка «уже обработан». С обычным Map такие записи жили бы вечно → **утечка памяти**.

## 5. Типовые паттерны

```ts
// Frequency count
const counts = new Map<string, number>();
for (const w of words) counts.set(w, (counts.get(w) ?? 0) + 1);

// Index by id: O(1) lookups instead of array.find each time
const byId = new Map(users.map((u) => [u.id, u]));

// Unique by key (keep first)
const seen = new Set();
const unique = items.filter((x) => !seen.has(x.id) && seen.add(x.id));

// Map → JSON
JSON.stringify(Object.fromEntries(map));
```

## 6. Частые вопросы на собесе (с ответами)

**Чем Map отличается от объекта?**
Любые типы ключей, порядок вставки, `size` за O(1), нет ключей из прототипа, прямая итерация. Минус — не сериализуется в JSON напрямую.

**Как убрать дубликаты из массива?**
`[...new Set(arr)]` — O(n).

**Почему `new Set([{a:1}, {a:1}]).size === 2`?**
Объекты сравниваются по ссылке, это два разных объекта.

**Почему `JSON.stringify(new Map([['a', 1]]))` → `'{}'`?**
Данные Map лежат во внутренних слотах, а не в свойствах объекта. Нужно `Object.fromEntries(map)`.

**Как найти пересечение двух массивов за O(n + m)?**
Один массив положить в Set, второй отфильтровать через `has`.

**Чем WeakMap отличается от Map и зачем он нужен?**
Ключи — только объекты и хранятся слабо, поэтому нет утечек памяти. Платим тем, что нельзя обойти и узнать размер.

**Что вернёт `map.set('a', 1)`?**
Сам Map, поэтому можно чейнить.
