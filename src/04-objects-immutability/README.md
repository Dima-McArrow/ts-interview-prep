## 1. Карточки `Object.*`

| Метод                           | Возвращает                                      | Мутирует?         | Заметки                                              |
| ------------------------------- | ----------------------------------------------- | ----------------- | ---------------------------------------------------- |
| `Object.keys(o)`                | массив **ключей** (строки)                      | нет               | только собственные перечисляемые                     |
| `Object.values(o)`              | массив **значений**                             | нет               |                                                      |
| `Object.entries(o)`             | массив пар `[key, value]`                       | нет               | мост «объект → методы массивов»                      |
| `Object.fromEntries(pairs)`     | **новый объект** из пар / Map / URLSearchParams | нет               | обратная к `entries`                                 |
| `Object.groupBy(arr, fn)`       | `{ key: T[] }` (null-prototype)                 | нет               | ES2024; для не-строковых ключей — `Map.groupBy`      |
| `Object.assign(target, ...src)` | **target**                                      | **ДА**            | `Object.assign({}, a, b)` ≈ `{ ...a, ...b }`         |
| `Object.freeze(o)`              | тот же объект                                   | да (замораживает) | **shallow**; запись в strict mode → `TypeError`      |
| `Object.isFrozen(o)`            | boolean                                         | нет               |                                                      |
| `Object.hasOwn(o, k)`           | boolean: **собственный** ключ?                  | нет               | замена `o.hasOwnProperty(k)`                         |
| `structuredClone(v)`            | **глубокая** копия                              | нет               | Date/Map/Set/циклы ✅; функции ❌ (`DataCloneError`) |

**Порядок ключей объекта:** сначала целочисленные ключи по возрастанию, затем строковые в порядке добавления. `Object.keys({ b: 1, 2: 'x', a: 1, 1: 'y' })` → `['1', '2', 'b', 'a']`.

### Главный паттерн: объект → пары → методы массивов → объект

```ts
const cheap = Object.fromEntries(Object.entries(prices).filter(([, p]) => p < 10));
const withTax = Object.fromEntries(Object.entries(prices).map(([k, p]) => [k, p * 1.2]));
const sorted = Object.fromEntries(Object.entries(prices).toSorted(([, a], [, b]) => a - b));
const query = Object.fromEntries(new URLSearchParams('page=2&q=js')); // { page: '2', q: 'js' }
```

## 2. Копирование: shallow vs deep

| Способ                             | Глубина     | Что теряется / ломается                                                                                  |
| ---------------------------------- | ----------- | -------------------------------------------------------------------------------------------------------- |
| `{ ...o }`, `Object.assign({}, o)` | **shallow** | вложенные объекты **общие** с оригиналом                                                                 |
| `JSON.parse(JSON.stringify(o))`    | deep        | `undefined` и функции исчезают, `Date` → строка, `Map`/`Set` → `{}`, `NaN` → `null`, циклы → `TypeError` |
| `structuredClone(o)`               | deep        | функции → `DataCloneError`, прототип класса (и методы) теряется                                          |

**Когда что:**

- обновление state → **ни то, ни другое**: structural sharing (копируем только путь до изменения);
- черновик формы, snapshot данных из API → `structuredClone`;
- JSON-копия — только если данные точно «чистый JSON».

## 3. Иммутабельные обновления (React/Redux)

| Операция            | Код                                                       |
| ------------------- | --------------------------------------------------------- |
| добавить            | `[...list, item]`                                         |
| удалить по id       | `list.filter((x) => x.id !== id)`                         |
| обновить по id      | `list.map((x) => (x.id === id ? { ...x, ...patch } : x))` |
| заменить по индексу | `list.with(i, item)`                                      |
| отсортировать       | `list.toSorted(cmp)`                                      |
| поле объекта        | `{ ...obj, field: value }`                                |
| вложенное поле      | `{ ...s, user: { ...s.user, city } }`                     |

**Structural sharing:** новые объекты создаются только на пути к изменению, остальное переиспользуется **по ссылке**. Благодаря этому `React.memo`, `useMemo` и селекторы Redux дёшево понимают, что изменилось (`prev === next`). Deep copy всего state эту оптимизацию ломает. Immer / Redux Toolkit генерируют structural sharing автоматически.

## 4. 🐛 Реальные баги (подробно — в лекции, секция 8, и на странице в Notion)

| Сценарий              | ❌ Причина                                                              | ✅ Фикс                                                      |
| --------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------ |
| Форма с «Отмена»      | `draft = { ...user }` — `address` общий                                 | копировать каждый меняемый уровень / `structuredClone`       |
| Кэш React Query / SWR | `data.sort()` мутирует массив из кэша                                   | `toSorted` / `[...data].sort()` / `select`                   |
| Undo/redo             | в историю кладут ссылку и потом мутируют                                | иммутабельные обновления, история хранит ссылки              |
| Node: shared defaults | `{ ...DEFAULTS }` + `push` в общий массив → права утекают между юзерами | фабрика `createDefaults()` / не мутировать / `Object.freeze` |

> **Правило:** чужие данные (props, кэш, state, shared-константы) — только читаем. Нужны изменения → новый объект, копируем ровно тот путь, который меняем.

## 5. `?.` и `??`

```ts
user?.address?.city; // undefined instead of TypeError
user.greet?.(); // call only if the method exists
list?.[0];

count ?? 0; // fallback ONLY for null / undefined
count || 0; // fallback for ANY falsy: 0, '', false, NaN, null, undefined
config.retries ??= 3; // assign only if null / undefined
config.name ||= 'Untitled'; // assign if falsy
```

| Значение слева | `x ?? 'def'` | `x \|\| 'def'` |
| -------------- | ------------ | -------------- |
| `undefined`    | `'def'`      | `'def'`        |
| `null`         | `'def'`      | `'def'`        |
| `0`            | **`0`**      | `'def'`        |
| `''`           | **`''`**     | `'def'`        |
| `false`        | **`false`**  | `'def'`        |

Для значений по умолчанию почти всегда нужен `??`: громкость `0` и пустая строка — валидные значения.

## 6. Сравнение объектов

- `===` — по ссылке. `{} === {}` → `false`.
- `Object.is(a, b)` — как `===`, но `Object.is(NaN, NaN)` → `true`, `Object.is(0, -0)` → `false`. **Так React сравнивает state и зависимости хуков.**
- По содержимому — свой `deepEqual` (задача T5) или `lodash.isEqual`. `JSON.stringify(a) === JSON.stringify(b)` зависит от порядка ключей и теряет `undefined`/`Date`.

## 7. Обход и проверка ключей

| Код                       | Что видит                                 |
| ------------------------- | ----------------------------------------- |
| `for (const k in obj)`    | собственные **и унаследованные** ключи ⚠️ |
| `Object.keys(obj)`        | только собственные ✅                     |
| `'k' in obj`              | есть ли ключ, **включая прототип**        |
| `Object.hasOwn(obj, 'k')` | есть ли **собственный** ключ              |

## 8. Частые вопросы на собесе (с ответами)

**Как сделать глубокую копию? Плюсы и минусы способов?**
`structuredClone` — корректно для данных (Date, Map, Set, циклы), но не копирует функции и прототип. JSON — теряет типы. Свой рекурсивный `deepClone` — задача T4.

**`Object.freeze` глубокий?**
Нет, замораживает только верхний уровень. Глубокая заморозка — рекурсивно (задача T6).

**Разница `??` и `||`?**
`??` срабатывает только на `null`/`undefined`, `||` — на любое falsy (`0`, `''`, `false`...).

**Почему `{} === {}` → `false`?**
Сравниваются ссылки; это два разных объекта.

**Зачем иммутабельность в React?**
React определяет изменения по ссылке (`Object.is`). Мутация сохраняет ссылку → нет ре-рендера. Иммутабельные обновления + structural sharing дают и корректность, и дешёвые проверки.

**Что вернёт `Object.assign(a, b)`?**
Сам `a`, уже изменённый.

**Чем `for...in` отличается от `Object.keys`?**
`for...in` включает унаследованные перечисляемые ключи.
