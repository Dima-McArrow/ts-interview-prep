## 0. Два вопроса, которые задают про КАЖДЫЙ метод

1. **Мутирует ли он исходный массив?** То есть меняет его «на месте», так что после вызова старая переменная указывает на изменённые данные.
2. **Что он возвращает?** Новый массив / один элемент / индекс / boolean / длину / `undefined`.

Почему это важно на практике: в React и Redux «изменилось ли состояние» определяется **по ссылке** (`prev === next`). Если ты мутировал массив, ссылка осталась та же → React думает, что ничего не изменилось → нет ре-рендера → баг. Поэтому мутирующие методы в state применяют только к копии.

## 1. Фундамент: примитивы vs объекты

| Примитивы                                                              | Объекты (всё остальное)                                |
| ---------------------------------------------------------------------- | ------------------------------------------------------ |
| `number`, `string`, `boolean`, `null`, `undefined`, `bigint`, `symbol` | `{}`, **массивы `[]`**, функции, `Date`, `Map`, `Set`… |
| хранятся **как значение**                                              | хранятся **по ссылке** (адрес в памяти)                |
| `===` сравнивает **значения**                                          | `===` сравнивает **адреса**                            |

**Массив — это объект** с ключами `"0"`, `"1"`, … и свойством `length`. Поэтому `typeof [] === 'object'`, а проверять «это массив?» нужно через `Array.isArray(x)`.

Аналогия: переменная хранит не сам массив, а **адрес квартиры**, где он лежит. `===` спрашивает не «одинаковая ли мебель?», а «это тот же адрес?».

```ts
const x = 5;
const y = 5;
x === y; // true  — примитивы: сравниваются значения

const a = [1, 2];
const b = [1, 2];
a === b; // false — два разных массива по двум адресам

const c = a; // копируется АДРЕС, не массив
c === a; // true  — один и тот же массив
c.push(3); // a тоже стал [1, 2, 3]

[1, 2] === [1, 2]; // 🪤 false — та же история, просто без имён
[] == []; // 🪤 false — == для двух объектов тоже сравнивает ссылки

JSON.stringify(a) === JSON.stringify(b); // true — сравнение по содержимому (для простых данных)
```

**Зачем это фронтендеру:** React решает, перерисовывать ли компонент, сравнивая старый и новый state **по ссылке** (`Object.is(prev, next)`). Сделал `state.push(x)` и передал тот же массив — адрес не изменился → React не видит изменений → нет ре-рендера. Поэтому state обновляют иммутабельно: `[...state, x]`, `map`, `filter`, `toSorted`.

### «Новый массив» = shallow copy

`map`, `filter`, `slice`, `toSorted`… возвращают **новый массив** (новый адрес). Но объекты внутри не копируются: в новый массив переносятся их **адреса**:

```ts
const users = [{ name: 'Ann' }];
const copy = users.filter(() => true);

copy === users; // false — массивы разные (разные адреса)
copy[0] === users[0]; // true  — объект внутри один и тот же
copy[0].name = 'Bob'; // и в users[0] тоже 'Bob'!
```

Чтобы «изменить» объект иммутабельно — создай новый: `users.map(u => ({ ...u, name: 'Bob' }))`.
Глубокая копия — `structuredClone(arr)` (урок 04).

## 2. Шпаргалка

### Не мутируют ✅

| Метод                                            | Возвращает                    | Если «ничего нет»        |
| ------------------------------------------------ | ----------------------------- | ------------------------ |
| `map(fn)`                                        | новый массив **той же длины** | `[]` на `[]`             |
| `filter(fn)`                                     | новый массив подходящих       | `[]`                     |
| `reduce(fn, init)`                               | **одно значение** любого типа | `init` (или 💥 без init) |
| `find(fn)` / `findLast(fn)`                      | элемент                       | `undefined`              |
| `findIndex` / `findLastIndex`                    | индекс                        | `-1`                     |
| `includes(v)`                                    | boolean                       | `false`                  |
| `indexOf(v)` / `lastIndexOf(v)`                  | индекс                        | `-1`                     |
| `some(fn)`                                       | boolean «хоть один»           | `false` на `[]`          |
| `every(fn)`                                      | boolean «все»                 | **`true` на `[]`**       |
| `slice(start, end)`                              | новый массив-кусок            | `[]`                     |
| `concat(...)`                                    | новый склеенный массив        |                          |
| `flat(depth)` / `flatMap(fn)`                    | новый расплющенный массив     |                          |
| `join(sep)`                                      | **строка**                    | `''`                     |
| `at(i)`                                          | элемент (поддерживает `-1`)   | `undefined`              |
| `toSorted` / `toReversed` / `toSpliced` / `with` | новый массив (ES2023)         |                          |
| `forEach(fn)`                                    | **всегда `undefined`**        |                          |

### Мутируют ⚠️

| Метод                          | Возвращает                      |
| ------------------------------ | ------------------------------- |
| `push(...x)` / `unshift(...x)` | **новую длину** (число!)        |
| `pop()` / `shift()`            | удалённый элемент / `undefined` |
| `splice(start, count, ...add)` | **массив удалённых**            |
| `sort(cmp?)`                   | **тот же** массив               |
| `reverse()`                    | тот же массив                   |
| `fill(v, start?, end?)`        | тот же массив                   |
| `copyWithin(...)`              | тот же массив (редкий)          |

## 3. Карточки методов

### `map(callback)` — преобразовать каждый элемент

- **Сигнатура:** `arr.map((value, index, array) => newValue)`
- **Возвращает:** новый массив **той же длины**; на месте каждого элемента — то, что вернул колбэк.
- **Мутирует:** нет.
- **Когда:** превратить данные в другой вид (объекты → имена, DTO → модель для UI, числа → строки).
- **Когда НЕ надо:** если результат не используешь → `forEach` / `for...of`. Если нужно выкинуть часть элементов → `filter` или `flatMap`.

```ts
[1, 2, 3].map((n) => n * 2); // [2, 4, 6]
users.map((u) => u.name); // ['Ann', 'Bob', ...]
users.map((u) => ({ ...u, age: u.age + 1 })); // новые объекты, оригинал цел
```

⚠️ **Подводные камни:**

- Забыл `return` в `{ }` → массив `undefined`: `arr.map(n => { n * 2 })`.
- Объект без скобок: `arr.map(u => { name: u.name })` — это тело функции с меткой `name:`, а не объект! Нужно `arr.map(u => ({ name: u.name }))`.
- `['1','2','3'].map(parseInt)` → `[1, NaN, NaN]`: map передаёт `(value, index)`, а `parseInt` воспринимает index как систему счисления. Фикс: `.map(Number)`.
- `new Array(3).map(...)` ничего не делает — map пропускает «дырки».

---

### `filter(callback)` — оставить подходящие

- **Сигнатура:** `arr.filter((value, index, array) => boolean)`
- **Возвращает:** новый массив с элементами, для которых колбэк вернул **truthy**. Если ничего — `[]`.
- **Мутирует:** нет.
- **Когда:** поиск по условию «все, кто…», удаление элемента иммутабельно (`filter(x => x.id !== id)`).

```ts
users.filter((u) => u.active);
[0, 1, '', 'a', null].filter(Boolean); // [1, 'a'] — убрать falsy
todos.filter((t) => t.id !== idToRemove); // иммутабельное удаление
```

⚠️ **Подводные камни:**

- `filter(Boolean)` выкинет и `0`, и `''` — если это валидные значения, пиши `x => x != null`.
- В TS для сужения типа нужен type guard: `arr.filter((x): x is string => x !== null)`.
- Если нужен **один** элемент — не `filter(...)[0]`, а `find` (он остановится на первом).

---

### `reduce(callback, initialValue)` — свернуть в одно значение

- **Сигнатура:** `arr.reduce((acc, value, index, array) => newAcc, initialValue)`
- **Как работает:** `acc = initialValue`; для каждого элемента `acc = callback(acc, value)`; вернуть `acc`.
- **Возвращает:** **одно** значение **любого** типа: число, строку, объект, Map, массив.
- **Мутирует:** нет.
- **Когда:** сумма/произведение/максимум, построить объект (счётчик, индекс по id, группировка), «развернуть» данные.

```ts
[1, 2, 3].reduce((acc, n) => acc + n, 0); // 6
words.reduce(
  (acc, w) => {
    acc[w] = (acc[w] ?? 0) + 1;
    return acc; // ← обязательно!
  },
  {} as Record<string, number>,
);
```

⚠️ **Подводные камни:**

- **Всегда передавай `initialValue`.** Без него на `[]` → `TypeError: Reduce of empty array with no initial value`.
- **Всегда возвращай `acc`.** Забыл → в следующей итерации `acc === undefined`.
- Тип `initialValue` задаёт тип результата: `[1,2,3].reduce((a, n) => a + n, '')` → `'123'`.
- Не используй `reduce` как замену `filter + map` «для скорости»: `[...acc, x]` на каждом шаге копирует массив → O(n²).

---

### `forEach(callback)` и `for...of`

- **`forEach` возвращает:** всегда `undefined`. Не чейнится.
- **Нельзя:** `break`, `continue`, нормальный `await` внутри.
- **`for (const x of arr)`** — умеет всё это. Индекс: `for (const [i, x] of arr.entries())`.
- **Правило:** нужен новый массив → `map`/`filter`; одно значение → `reduce`/`find`; просто действие → `for...of`.

---

### `find` / `findLast` / `findIndex` / `findLastIndex`

- **Сигнатура:** `arr.find((value, index, array) => boolean)`
- **Возвращает:** `find` — первый подходящий **элемент** или `undefined`; `findIndex` — его **индекс** или `-1`. `findLast*` (ES2023) — то же с конца.
- **Мутирует:** нет. **Останавливается** на первом совпадении.

```ts
users.find((u) => u.id === 2); // объект или undefined
users.findIndex((u) => u.id === 2); // 1 или -1
```

⚠️ `if (index)` — баг: индекс `0` falsy, а `-1` truthy. Пиши `if (index !== -1)`.

---

### `includes(value)` vs `indexOf(value)`

- Принимают **значение**, а не функцию. Сравнивают почти как `===`.
- `includes` → boolean, видит `NaN` (алгоритм SameValueZero).
- `indexOf` → индекс или `-1`, **не** видит `NaN` (строгое `===`, а `NaN !== NaN`).
- Объекты — **по ссылке**: `[{a:1}].includes({a:1})` → `false`. Для поиска по содержимому — `some`.

---

### `some(fn)` / `every(fn)`

- `some` → `true`, если **хоть один** подходит. Останавливается на первом `true`.
- `every` → `true`, если **все** подходят. Останавливается на первом `false`.
- **На пустом массиве:** `some` → `false`, `every` → **`true`** (vacuous truth: «нет ни одного, кто не прошёл бы»).

---

### `slice(start?, end?)` — копия куска (НЕ мутирует)

- Интервал `[start, end)` — `end` **не включается**. Отрицательные индексы — с конца.
- `slice()` без аргументов — shallow copy всего массива.

```ts
['a', 'b', 'c', 'd'].slice(1, 3); // ['b', 'c']
['a', 'b', 'c', 'd'].slice(-2); // ['c', 'd']
```

Мнемоника против путаницы со `splice`: **s-P-lice = Plus side effects** (мутирует).

---

### `splice(start, deleteCount?, ...items)` — вырезать/вставить (МУТИРУЕТ)

- **Возвращает:** массив **удалённых** элементов.
- Удалить: `arr.splice(i, 1)`. Вставить: `arr.splice(i, 0, x, y)`. Заменить: `arr.splice(i, 1, x)`.
- Иммутабельная версия: `toSpliced` (ES2023) или `filter` / `slice` + spread.

---

### `sort(compareFn?)` — сортировка (МУТИРУЕТ)

- **Возвращает:** **тот же** массив (не копию!).
- **Без компаратора** сравнивает элементы **как строки**: `[10, 1, 5].sort()` → `[1, 10, 5]`.
- **Компаратор** `(a, b) => number`: `< 0` — `a` раньше; `> 0` — `b` раньше; `0` — неважно.

```ts
nums.sort((a, b) => a - b); // по возрастанию
nums.sort((a, b) => b - a); // по убыванию
names.sort((a, b) => a.localeCompare(b)); // строки
users.sort((a, b) => a.age - b.age || a.name.localeCompare(b.name)); // 2 ключа
const sorted = users.toSorted(...); // без мутации (ES2023)
```

- С 2019 года сортировка **стабильная**: равные элементы сохраняют исходный порядок.

---

### `push` / `pop` / `shift` / `unshift` (МУТИРУЮТ)

| Метод        | Куда     | Возвращает        | Скорость |
| ------------ | -------- | ----------------- | -------- |
| `push(x)`    | в конец  | **новую длину**   | O(1)     |
| `pop()`      | с конца  | удалённый элемент | O(1)     |
| `unshift(x)` | в начало | **новую длину**   | O(n)     |
| `shift()`    | с начала | удалённый элемент | O(n)     |

Иммутабельно: добавить — `[...arr, x]` / `[x, ...arr]`; удалить последний — `arr.slice(0, -1)`.

---

### `flat(depth = 1)` / `flatMap(fn)`

- `flat` — расплющить на `depth` уровней (`Infinity` — до конца).
- `flatMap(fn)` = `map(fn).flat(1)`. Колбэк возвращает массив из 0..N элементов → умеет одновременно фильтровать и размножать.

```ts
[1, [2, [3]]].flat(); // [1, 2, [3]]
['a b', 'c'].flatMap((s) => s.split(' ')); // ['a', 'b', 'c']
[1, 2, 3].flatMap((n) => (n > 1 ? [n] : [])); // [2, 3]
```

---

### `at(i)`, `join(sep)`, `concat(...)`

- `at(-1)` — последний элемент. `arr[-1]` → `undefined` (это свойство `"-1"`, а не индекс с конца).
- `join(', ')` → строка. По умолчанию разделитель `','`. `null`/`undefined` → пустые строки.
- `concat` склеивает и раскрывает массивы-аргументы на 1 уровень. Аналог `[...a, ...b]`.

---

### ES2023: `toSorted`, `toReversed`, `toSpliced`, `with`

Иммутабельные двойники `sort`, `reverse`, `splice` и `arr[i] = v`. Возвращают **новый** массив. Идеальны для React state.

```ts
const next = todos.with(index, { ...todos[index], done: true });
```

---

### Создание: `Array.from`, `Array.of`, `new Array`, `Array.isArray`

| Код                                      | Результат                              |
| ---------------------------------------- | -------------------------------------- |
| `Array.from({ length: 3 }, (_, i) => i)` | `[0, 1, 2]`                            |
| `Array.from('abc')`                      | `['a', 'b', 'c']`                      |
| `Array.from(new Set([1, 1, 2]))`         | `[1, 2]`                               |
| `[...new Set(arr)]`                      | убрать дубликаты                       |
| `new Array(3)`                           | 3 **пустых слота** (map их пропускает) |
| `new Array(3).fill(0)`                   | `[0, 0, 0]`                            |
| `new Array(3).fill([])`                  | ⚠️ 3 ссылки на **один** массив         |
| `Array.of(3)`                            | `[3]`                                  |
| `Array.isArray(x)`                       | единственная надёжная проверка         |

---

## 4. Как выбрать метод

```
Нужен новый массив той же длины?           → map
Нужно оставить часть элементов?            → filter
Нужно одно значение (сумма, объект)?       → reduce
Нужен один элемент?                        → find / findLast
Нужен индекс?                              → findIndex / indexOf
Есть ли значение?                          → includes   (по условию → some)
Все ли подходят?                           → every
Отсортировать без мутации?                 → toSorted
Кусок массива?                             → slice
Убрать вложенность?                        → flat / flatMap
Просто пройтись (с break/await)?           → for...of
```

## 5. Частые вопросы на собесе (с ответами)

**Чем `map` отличается от `forEach`?**
`map` возвращает новый массив из результатов колбэка; `forEach` возвращает `undefined` и нужен для side effects.

**Чем `slice` отличается от `splice`?**
`slice` возвращает копию куска и не мутирует; `splice` вырезает/вставляет на месте и возвращает удалённые элементы.

**Почему `[10, 1, 5].sort()` даёт `[1, 10, 5]`?**
Без компаратора элементы сравниваются как строки, а `'10' < '5'`.

**Что вернёт `[].every(x => false)`?**
`true` — на пустом массиве нет ни одного элемента, нарушающего условие.

**Как удалить дубликаты?**
`[...new Set(arr)]` — O(n). Через `filter((x, i) => arr.indexOf(x) === i)` — O(n²).

**Как сделать копию массива?**
`[...arr]`, `arr.slice()`, `Array.from(arr)` — все shallow. Глубокая — `structuredClone(arr)`.

**Что вернёт `arr.push(x)`?**
Новую длину массива, а не сам массив.

**Почему `['1','2','3'].map(parseInt)` → `[1, NaN, NaN]`?**
`map` передаёт `(value, index)`, `parseInt` воспринимает index как radix.
