## 1. Область видимости (scope)

- **Лексическая:** функция видит переменные места, где она **написана**, а не откуда её **вызвали**.
- **Цепочка областей:** поиск переменной идёт изнутри наружу: своя функция → внешняя → … → глобальная.
- **`let` / `const`** — блочная область (`{ }`). **`var`** — функциональная (игнорирует блоки `if`/`for`), и поэтому его не используют.

## 2. Замыкание (closure)

**Функция + ссылка на переменные окружения, где она была создана.** Переменные живут, пока на них ссылается хоть одна функция.

```ts
function createCounter() {
  let count = 0; // private, lives in the closure
  return () => ++count;
}
const next = createCounter();
next(); // 1
next(); // 2
```

- Каждый вызов фабрики → **новое** замыкание со своими переменными.
- Хранится **ссылка на переменную**, а не снимок значения: переменная изменилась → функция видит новое.
- **Stale closure** (React): колбэк замкнул переменную из **старого** рендера (`useEffect`/`setInterval` «видит старый state»). Лечится зависимостями, функциональным `setState(prev => ...)` или `useRef`.

**Где используется:** приватное состояние, фабрики, модули, `once`/`memoize`/`debounce`/`throttle`, каррирование, обработчики событий, хуки.

### Классика: `var` vs `let` в цикле

```ts
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 3 3 3
for (let i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 0 1 2
```

`var` — **одна** переменная на весь цикл (к моменту колбэков она = 3). `let` — **новая** переменная на каждую итерацию.

## 3. Функции высшего порядка на замыканиях

| Утилита            | Что делает                                                   | Где применяют                   |
| ------------------ | ------------------------------------------------------------ | ------------------------------- |
| `once(fn)`         | вызвать `fn` один раз, дальше отдавать запомненный результат | инициализация SDK, подключения  |
| `memoize(fn)`      | кэш результатов по аргументам (`Map`)                        | тяжёлые вычисления, `useMemo`   |
| `debounce(fn, ms)` | вызвать через `ms` после **последнего** вызова               | поиск при вводе, автосохранение |
| `throttle(fn, ms)` | вызывать **не чаще** раза в `ms`                             | scroll, resize, mousemove       |
| `curry(fn)`        | `f(a, b, c)` → `f(a)(b)(c)`                                  | частичное применение            |

Шаблон у всех один:

```ts
function wrapper(fn) {
  // state lives here (closure)
  return (...args) => {
    /* read/update state, call fn(...args) */
  };
}
```

**debounce vs throttle:** debounce — лифт, ждущий, пока все зайдут (каждый новый сбрасывает таймер). Throttle — автобус по расписанию: уезжает раз в N минут.

## 4. `this` — определяется в момент **вызова**

| Как вызвали             | `this`                                                |
| ----------------------- | ----------------------------------------------------- |
| `obj.method()`          | `obj`                                                 |
| `fn()`                  | `undefined` (strict mode / модули)                    |
| `new Fn()`              | новый объект                                          |
| `fn.call(ctx, a, b)`    | `ctx`, вызов **сразу**, аргументы списком             |
| `fn.apply(ctx, [a, b])` | `ctx`, вызов **сразу**, аргументы **массивом**        |
| `fn.bind(ctx)`          | **новая функция**, `this` привязан **навсегда**       |
| стрелочная функция      | `this` снаружи (лексический); `call`/`bind` не меняют |

**Потеря контекста:** `const f = obj.method; f()`, `setTimeout(obj.method)`, `arr.forEach(obj.method)`, `el.addEventListener('click', obj.method)` — везде `this` = `undefined`.

**Фиксы:** обёртка-стрелка `() => obj.method()`, `obj.method.bind(obj)`, метод-стрелка в классе (`handle = () => {...}`).

### Стрелочные функции

- Нет своего `this` (берут снаружи), нет `arguments`, нет `prototype`, нельзя `new`.
- ✅ Стрелка **внутри** метода (колбэк `map`/`setTimeout`) видит `this` метода.
- ❌ Стрелка **как** метод объектного литерала: `this` будет не объектом.

## 5. Итераторы

- **Iterable** — есть `[Symbol.iterator]()`, возвращающий **итератор**.
- **Итератор** — есть `next()` → `{ value, done }`.
- Через этот протокол работают: `for...of`, `[...x]`, `[a, b] = x`, `Array.from`, `new Map/Set(x)`, `Promise.all(x)`.
- Iterable из коробки: Array, String, Map, Set, NodeList, arguments, генераторы. **Обычный объект — нет.**

## 6. Генераторы `function*`

```ts
function* gen() {
  yield 1; // pause here, give 1
  yield 2;
  return 3; // ignored by for...of / spread
}
const it = gen(); // body has NOT started yet
it.next(); // { value: 1, done: false }
```

- Тело выполняется **кусками** — до следующего `yield` на каждый `next()`.
- **Ленивые**: можно описать бесконечную последовательность и брать сколько нужно.
- Объект-генератор **одноразовый**. Нужен многоразовый — возвращай объект с `*[Symbol.iterator]() {...}`.
- `yield* other` — делегировать другому iterable (удобно для рекурсивных обходов).
- Node 22+: **iterator helpers** — `gen().map().filter().take(5).toArray()` (ленивые, без промежуточных массивов).

## 7. Частые вопросы на собесе (с ответами)

**Что такое замыкание? Пример из практики.**
Функция, которая помнит переменные окружения создания. Пример: `debounce` хранит таймер в замыкании; React-хуки.

**Почему `var` в цикле с `setTimeout` печатает `3 3 3`?**
Одна переменная на весь цикл; колбэки выполняются после цикла, когда `i = 3`. `let` создаёт новую переменную на каждую итерацию.

**Разница `call`, `apply`, `bind`?**
`call`/`apply` вызывают сразу (аргументы списком / массивом), `bind` возвращает новую функцию с привязанным `this`.

**Чем стрелочная функция отличается от обычной?**
Нет своего `this` и `arguments`, нельзя `new`, нет `prototype`.

**Напишите `debounce`. Чем отличается от `throttle`?**
См. таблицу выше и задачи T4/T5.

**Как сделать объект итерируемым?**
Добавить метод `[Symbol.iterator]()`, возвращающий итератор (проще всего — генератор `*[Symbol.iterator]() { ... }`).

**Что вернёт `bound.call(other)`, если `bound = fn.bind(obj)`?**
`this` останется `obj`: `bind` привязывает навсегда.
